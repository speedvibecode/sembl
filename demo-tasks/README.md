# Demo Proof — Phase 0

Controlled A/B demos on real, popular, medium-sized repos: the **same executor agent**
performs the **same task** twice — once from a raw prompt (arm `raw`), once from a
Sembl Work Order executor prompt (arm `sembl`). We measure shape, not intelligence:

- files touched / out-of-scope files
- diff size (lines)
- validation tests passed first try
- reviewer notes

Targets are **cloned at a pinned SHA, never vendored** (license + cleanliness). This
repo holds only task definitions and result artifacts.

## Structure

```
demo-tasks/<app>/<NNN-task>/
  task.md                  ← task provenance: source issue, reference fix, pinned SHA
  raw-prompt.md            ← messy prompt given verbatim to arm `raw`
  sembl-work-order.md      ← Work Order generated by `sembl generate` from the same text
  executor-prompt.md       ← the only input arm `sembl` receives
  expected-scope.json      ← file set of the human reference fix (one valid solution)
  validation-command.txt   ← command run after each arm
  pinned-sha.txt           ← target repo commit both arms start from
  results/<arm>-<model>/   ← diff.patch, files_changed.txt, test_result.txt, notes.md
```

## Executor matrix

Each arm runs across executor tiers (haiku → sonnet → opus → fable) to observe how the
Work Order delta varies with executor strength. Each run starts from a clean branch at
the pinned SHA; agents never see each other's work.

## Claim discipline

We are not claiming Sembl makes models smarter. We test whether the SAME agent performs
better when work is shaped as a scoped Work Order. The reference fix is ONE valid
solution; expected-scope is a scope yardstick, not a correctness oracle.
